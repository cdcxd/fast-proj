# RESULTS: wasm simd UTM kernel experiment

Branch `experiment/utm-wasm`. Kernel: Rust (stable 1.99, wasm32-unknown-unknown),
f64x2 simd128, batch ABI over a bump-arena heap; full `Utm` API surface via
`wasm-utm.mjs` (node) / `wasm-utm-core.mjs` (environment-agnostic).

Machine: AMD Ryzen 9 3900X, Linux x64. Runtimes: Node v24.21.0, Bun 1.4.2,
Chromium 150.0.7871.124 (headless via Playwright, `CHROME=/usr/bin/google-chrome`).

## Accuracy (3-way: wasm vs TS kernel vs proj4)

`bench/accuracy.mjs` — 80 grid combinations (±30°/±45° from CM × 5 ellipsoids
[sphere, WGS84, GRS80, f=0.005, f=0.0099999] × zones 1/31/33/60 × both
hemispheres × 188 latitudes incl. near-poles and signed zero):

- wasm vs TS: forward ≤ 3.7e-9 m; inverse ≤ 5.7e-14° (cos-weighted lon), ≤ 2.8e-14° lat
- wasm vs proj4 and TS vs proj4: both ≤ 7.5e-9 m, identical worst rows — the
  wasm kernel is exactly as accurate as the TS kernel against an independent
  reference (a pure wasm-vs-TS diff could not have hidden a shared error)
- classification (finite/NaN/±Inf) and signed-zero parity: 0 mismatches
- independent fixture (zone 31, 91 pts): ≤ 1.9e-9 m, ≤ 2.8e-14°
- beyond the grid, extended random sweeps (200k pts, lat ±84°, zone ±3.55°)
  stay single-digit nanometers (3.7–5.6 nm across seeds, worst near
  mid-latitudes) — the 3.7 nm figure above is the grid, not a global bound

Gates also green: host `cargo test --release` (6 tests), `bench/checks.mjs`
(quadrants, atan/log/exp seams incl. `atan2(±Inf,±Inf)`, tails, allocator,
equator signed zeros, guard classification, out-of-domain diagnostics parity,
grid sweep) on Node and Bun, `bench/sweeps.mjs` (≤ 2 ulp), and
`bench/wrapper-checks.mjs` (API surface incl. CAP-chunk boundaries, plain-Array
sources, out-param validation — on the real wasm path, gated by a
`kernel === 'wasm-simd'` assertion so a silent TS fallback cannot pass), plus a
full IEEE quadrant table for `atan2_batch` vs `Math.atan2` (±0/±Inf/NaN).

## Performance (TS kernel = 1.0x; higher is better)

n=10 000 — repo protocol `packages/utm/bench/compare-performance.mjs`
(fresh worker process per revision, order alternating over 3 rounds, 51 runs ×
5 reps, 150 warmups, median):

| runtime      | dataset | forward | inverse |
| ------------ | ------- | ------- | ------- |
| Node 24.21   | UTM     | 1.996x  | 1.971x  |
| Node 24.21   | wide    | 1.952x  | 1.930x  |
| Bun 1.4.2    | UTM     | 1.325x  | 1.680x  |
| Bun 1.4.2    | wide    | 1.450x  | 1.695x  |
| Chromium 150 | UTM     | 3.516x  | 3.129x  |
| Chromium 150 | wide    | 3.516x  | 3.267x  |

n=1 000 000 — `bench/perf-1e6.mjs`, same discipline (fresh process per
revision, 3 alternating rounds, median of 15, checksum-guarded):

| runtime    | forward                  | inverse                  |
| ---------- | ------------------------ | ------------------------ |
| Node 24.21 | 1.748x (120.2 → 68.8 ms) | 1.727x (116.1 → 67.2 ms) |
| Bun 1.4.2  | 1.255x (86.5 → 69.0 ms)  | 1.509x (98.6 → 65.3 ms)  |

Chromium is report-only (no 1e6 leg; its TS baseline is 2.5–3x slower than
Node's, so wasm gains are largest there).

## Decision vs the bar

Bar (PROPOSAL.md): ship opt-in `@fast-proj/utm/wasm` iff **≥ 1.4x on Node AND
Bun at n=1e6, forward+inverse**; 1.25–1.4x is a judgment call; < 1.25x close.

- Node: 1.73–1.75x — clears.
- Bun: inverse 1.51x clears; **forward 1.26x sits at the bottom of the
  judgment band** (Bun's JIT-inlined `Math.*` at 1e6 is the strongest TS
  baseline of the three runtimes; the wasm kernel itself runs ~65–69 ms
  regardless of host, so this cell tracks Bun's baseline, not our kernel).

Judgment: ship as an **opt-in subpath** (`@fast-proj/utm/wasm`), default
export unchanged. The only sub-bar cell is Bun-forward at 1e6, every other
cell is 1.54–3.5x, and opt-in means no caller regresses. Revisit if Bun's
baseline widens the gap further.

## Artifacts

- `build/simd.wasm` 20.1 kB (kernel + scalar reference twin), `build/scalar.wasm`
  17.5 kB. Self-contained bench candidate `utm.js` (base64-inline artifact,
  27.8 kB) is generated by `scripts/embed-artifact.sh` and gitignored.
- Wrapper: allocate-once 64 Ki-point scratch (2 MiB) in a fixed 256 MiB wasm
  arena (never grows, so cached views stay valid); larger batches chunk;
  `.set()`-based copies (memcpy-grade); simd128 feature-detect with TS fallback
  (`kernel: 'wasm-simd'` marker on the wasm path).
- Every `utmWasm()` instance costs ~2 MiB of arena; the arena traps loudly in
  release builds when exhausted (≈ 128 instances at 2 MiB each).

## Notes

- Guarded atan sites are hoisted per pair: in-domain lanes (cx > 0, finite)
  pay only `vatan`; any out-of-domain lane falls back to the `vatan2` blend.
  NaN/±0/boundary lanes always take the guarded path — verified by the
  quadrant/seam/classification checks above.
- `vexp` clamps its k term at ±1000 (|η| ≤ 693 in practice): diagnostics stay
  correct for |x| ≤ ~1.3e9 m; classification parity with TS holds to
  ~4.4e9 m, beyond which vexp yields a finite ~2^1000 where libm gives Inf.
  Out of scope for coordinates; documented for diagnostics parity.
- The simd128 feature probe is a hand-encoded module
  (`(func (result f64) f64x2.extract_lane 0 (v128.const i64x2 0 0))`) — an
  earlier revision had malformed bytes and silently forced the TS fallback on
  every call; wrapper-checks now asserts the wasm path is live.
- Devcontainer bundles the Rust toolchain (`.devcontainer/devcontainer.json`
  `features.rust`); builds via `scripts/build.sh` (cargo release →
  wasm32-unknown-unknown, simd + scalar).

## Reproduce

```sh
# repo root: install deps and build the TS baseline (packages/utm/dist/utm.js)
bun install && bun run build

cd experiments/utm-wasm
cargo test --release                 # host gate
bash scripts/build.sh                # build/simd.wasm + scalar.wasm
bash scripts/embed-artifact.sh       # regenerate self-contained utm.js
node bench/checks.mjs && bun bench/checks.mjs
node bench/wrapper-checks.mjs && bun bench/wrapper-checks.mjs
node bench/accuracy.mjs              # 3-way gate (needs repo-root proj4)

cd ../..   # repo root again
node packages/utm/bench/compare-performance.mjs \
  --base=packages/utm/dist/utm.js --candidate=experiments/utm-wasm/utm.js
bun packages/utm/bench/compare-performance.mjs \
  --base=packages/utm/dist/utm.js --candidate=experiments/utm-wasm/utm.js
CHROME=/usr/bin/google-chrome node packages/utm/bench/compare-performance.mjs \
  --base=packages/utm/dist/utm.js --candidate=experiments/utm-wasm/utm.js --browser
node experiments/utm-wasm/bench/perf-1e6.mjs
node experiments/utm-wasm/bench/perf-1e6.mjs --runtime=bun
```
